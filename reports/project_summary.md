# 电商用户行为分析：项目总结与面试准备

## 1. 一句话介绍

我基于约一亿条电商行为记录，用 SQL 和 Python 分析九天内的活跃、转化、留存与重复购买，并以 RF + 行为特征识别不同运营人群。

## 2. 为什么做

我希望展示从业务问题、数据口径、分析验证到运营解释的完整过程，而不是只展示查询或图表。项目面向数据分析、策略运营与用户运营岗位，是公开数据作品集，不是企业内部项目。

## 3. 我负责了什么

我整理了数据清洗与去重口径，完成平台行为、集合与严格顺序漏斗、首次观测 cohort 留存、跨日重复购买和规则分层；再用 Python 核对 SQL 结果，生成中文画像图表与运营建议。项目没有机器学习模型或已验证的营销效果，面试时只介绍自己能解释和复现的部分。

## 4. 分析思路

先确定每条记录是什么，再检查时间范围、行为类型和重复记录。随后从整体活跃进入转化、留存与购买日期频次，最后结合购买新近度、活跃与意向行为分层。

关键口径：

- buy 是事件，不是订单；相同日期多条 buy 不构成跨日重复购买。
- 无序集合漏斗不证明严格路径；严格路径另要求同用户、同商品、时间递增。
- 留存基于窗口内首次观测活跃，不是新注册 cohort；没有完整后续窗口的单元格为 NULL。
- Recency 固定锚定 2017-12-03；Frequency 优先采用不同购买日期数。
- 阈值来自实际分位点，群体按规则优先级互斥，不能把标签解释成长期生命周期。

## 5. 最重要的五个发现

| 发现 | 数据证据 | 业务解释 |
|---|---|---|
| 窗口内重复购买 | 370,274 / 672,404 位购买用户跨日购买，55.07% | 存在重复购买行为，但不是长期复购率 |
| 高活跃未购买 | 105,478 人，平均活跃 8.48 天、浏览 118.25 次，90.01% 有加购或收藏 | 值得调查兴趣到购买之间的障碍 |
| 加购未购买 | 129,320 人，占未购买用户 40.98%，平均加购 4.85 次 | 有意向信号，可研究召回机会 |
| 购买沉寂仍活跃 | 154,066 人，97.67% 在最后一天仍活跃 | 不能仅凭购买 Recency 判为流失 |
| 高参与购买 | 63,055 人，平均购买日期 4.07 天、购买品类 5.68 个 | 行为参与强，不代表金额贡献最高 |

## 6. 最值得讲的发现：购买沉寂但仍保持平台活跃

购买沉寂群体由购买 Recency 大于购买人群 Q75（4 天）识别，平均距最后购买 6.28 天。我进一步看最近平台活跃，发现 97.67% 在窗口最后一天仍有行为，平均浏览 96.84 次、加购 5.81 次。

这说明“没有再次购买”和“离开平台”是不同状态。若直接叫流失用户，可能把仍在比较商品或等待合适购买时机的人误归为流失。具体原因没有数据证明，但运营上值得先结合浏览兴趣与品类节奏研究再购买机会，再与真正平台不活跃者区分。

## 7. 一分钟回答：最后给业务什么建议？

> 我会优先研究三类人。第一类是高活跃未购买用户，平均活跃八天多，九成有加购或收藏，可以先调查浏览到购买的障碍，再测试推荐或优惠。第二类是加购未购买用户，可以考虑购物车召回，但价格和库存提醒需要补实时商品数据。第三类是购买沉寂但仍活跃用户，他们多数最后一天还在平台，可以结合近期兴趣测试再购买推荐，而不是直接按流失召回处理。对高参与购买用户，可测试权益和新品推荐。这些都是待验证方向，需用随机分组、统一观察窗口和增量购买及成本指标评估，当前数据没有证明策略有效。

## 8. 30–45 秒回答：最大的局限是什么？

> 最大局限是只有九天，窗口前历史和窗口后购买不可见。所以首次观测日不是注册日，没看到再次购买也不代表长期流失。其次没有订单 ID、金额和价格，buy 只是购买事件，不能计算真实订单频次、消费金额或长期价值。另外数据是公开样本，不能代表平台全量人群。我把结论限定为窗口内行为，并把运营建议写成需要测试的假设。

## 9. 为什么没有做标准 RFM？

> 数据没有交易金额，不能人为构造 Monetary 再称为标准 RFM。我采用 RF + Behavioral Segmentation：R 是距观测期结束的最后购买天数，F 优先用不同购买日期数，再结合活跃、浏览、收藏和加购。这样可以解释参与和意向，但不会把频次冒充金额价值。

## 10. 如果给更多数据，下一步做什么？

| 补充数据 | 可研究方向 |
|---|---|
| 订单 ID、金额、退款与商品价格 | 真实订单频次、净消费金额、标准 RFM；更长历史支持 CLV |
| 注册日期与更长观察期 | 真正新用户 cohort retention、长期留存与生命周期 |
| 曝光、Session 与商品信息 | 有归因窗口的转化分析，随后评估 conversion modeling |
| 营销触达、优惠券使用、成本与实验分组 | 优惠响应、campaign uplift / A/B testing |
| 更长历史与可验证的流失定义 | churn modeling，并用时间划分验证防止信息泄漏 |

这些是下一阶段方向，本项目没有实现上述模型。进一步建模前，应先补齐业务定义与数据质量，而不是为展示技术而增加复杂模块。

## 11. 分层细节与复现入口

“其他已购买”共 108,051 人，购买 Recency 为 3–4 天、购买日期为 1–2 天，平均活跃 7.36 天；这是规则的中间状态，不是异常用户。可记录为未来解释优化，不在本次改动规则。
