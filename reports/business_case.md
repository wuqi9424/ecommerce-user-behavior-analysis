# 流量增长后的购买承接：用户 × 品类运营决策案例

我基于公开电商行为数据，围绕“第二个周末流量增长，但购买承接相对不足”梳理问题、识别候选人群，并提出需要真实实验验证的运营方案。这是一份业务决策案例，没有真实营销上线结果。

分析范围为 **2017-11-25 至 2017-12-03，Asia/Shanghai**，包含 **100,095,182 条有效行为、987,991 名用户**。购买指观测到 buy 行为，不能等同于真实订单。

## 一、业务背景与问题

2017-12-02 至 12-03 的浏览用户与活跃用户规模明显高于前一个周末，但购买用户增长没有同步跟上，用户级集合漏斗比例下降。

业务上需要回答六个问题：

1. 增长来自更多用户，还是每名用户产生了更多行为？
2. 哪个转化环节的承接值得优先检查？
3. 哪些用户表现出较强购买意向，却没有观测到购买？
4. 哪些品类的流量与意向增长没有被购买增长同步承接？
5. 资源有限时，先触达哪些用户与品类组合？
6. 如何验证运营动作是否带来增量购买，而不是把自然购买归功于触达？

我先使用两个连续两天的周末进行对比，再结合用户画像与品类结果形成候选运营池，最后用实验设计明确验证方式。等长周末减少了窗口长度与星期结构的差异，但不能控制促销、流量来源或用户构成变化。

## 二、关键诊断：人数增长与比例下降同时发生

下面均为**日均用户数或每日比例的算术均值**，不是两天去重用户数对应的 period-level rate。

| 指标 | Previous weekend：11/25–11/26 | Final weekend：12/02–12/03 |
|---|---:|---:|
| 日均活跃用户 | 711,078.5 | 968,689 |
| 日均浏览用户 | 691,411 | 937,907 |
| 日均意向用户（收藏或加购） | 321,557 | 431,845.5 |
| 日均购买用户 | 134,335 | 173,856 |
| 每日浏览→意向比例均值 | 44.6238% | 43.9293% |
| 每日意向→购买比例均值 | 24.2194% | 22.1345% |
| 每日浏览→购买比例均值 | 18.2785% | 17.1709% |
| 每日完整集合漏斗比例均值 | 10.8077% | 9.7233% |

来源：[平台分析](../sql/03_platform_overview.sql)、[等长周末漏斗](../sql/04_conversion_funnel.sql)、[活跃与购买行为](../sql/05_retention_repeat_behavior.sql)。活跃指任意行为；意向指 fav 或 cart，人数按日去重。

平台漏斗中，浏览→意向为“浏览且有意向 / 浏览”；意向→购买为“浏览、意向、购买均发生 / 浏览且有意向”；浏览→购买为“浏览且购买 / 浏览”。完整集合比例为“三类行为均发生 / 浏览”。它们是无序集合关系，不证明同商品或先后购买路径；表中的日均意向人数包含所有意向用户，不等于嵌套漏斗的中间层人数。

**判断与决策含义：**购买人数确实增加，但浏览人群扩张更快，因而购买规模上升与浏览→购买比例下降可以同时成立。浏览→意向和意向→购买均下降，其中后者的百分点降幅更大，值得优先检查意向用户的购买承接；这不是证明某个流程故障，也不能排除人群构成变化。

[增长来源拆解](../sql/09_growth_decomposition.sql)补充了两天去重口径：活跃用户 **864,829 → 986,594（+14.08%）**，总事件 **21,084,602 → 27,440,018（+30.14%）**，人均事件 **24.38 → 27.81（+14.08%）**。规模与强度均增长，不能将其归为“用户扩张、单用户强度没有跟上”。这与每日比例下降不冲突：更频繁的行为不必然对应更多购买用户。

固定先改变规模、再改变强度的 bridge，将事件增量拆成约 **296.86 万**的规模分量与 **338.68 万**的强度分量。两者都重要，但交互项随顺序归属变化，这不是唯一或因果贡献率。PV 与 Fav 的两个分量相近，Cart 的强度分量更大，Buy 的规模分量略大；四类人均行为次数均增长。

Final weekend 中首次观测用户仅 **19 人（0.001926%）**，贡献 **201 条事件**；此前已观测用户有 **986,575 人**。两组人均事件为 **10.58 / 27.81**，购买用户率为 **57.89% / 30.81%**，前组仅 19 人，不能据此推断稳定差异或原因。增长主要体现此前已观测用户参与，不构成真实获客证据；没有 acquisition channel、campaign / promotion、traffic source 或 exposure log，无法判断流量来源。

## 三、用户机会识别

现有 RF + 行为特征分层没有消费金额维度，标签描述九天内的相对行为状态。这里沿用已验证规则，不另建分层。

**高活跃未购买用户：**共 **105,478 人**，平均活跃 **8.48 天**、浏览 **118.25 次**，其中 **90.01%** 有收藏或加购。持续参与与意向信号同时存在，适合进一步调查兴趣到购买的障碍，而不是直接判断这些人一定会购买。

**加购未购买用户：**最终分层中有 **129,320 人**，占未购买用户 **40.98%**，平均加购 **4.85 次**。相较单纯浏览，加购体现了把商品放入购物车的具体动作，可作为优先测试的意向信号，但当前数据没有证明其购买概率或未购买原因。高活跃未购买规则先于加购规则，因此这一群体不等于所有加购但未购买用户。

**购买沉寂观察用户：**共 **154,066 人**，平均距最后购买 **6.28 天**，但 **97.67%** 在最后一天仍有平台行为。购买沉寂与平台不活跃应分别处理；这批用户可考虑再购买推荐测试，不能直接标为流失。

来源：[用户分层](../sql/06_user_segmentation.sql)、[画像结果与总结](project_summary.md)。

面向下一轮运营，进一步将近期信号落到 **user_id × category_id**：

- **P1：**12/02–12/03 有 cart，且九天内目标品类没有 buy。
- **P2：**近期无 cart、有 fav，且九天内目标品类没有 buy。
- **P3：**近期无 cart/fav，浏览次数达到数据驱动阈值，且九天内目标品类没有 buy。阈值为纯浏览未买组合近期 PV 次数的 Q75，实际为 **2 次**；“高浏览”只表示该分布中的相对位置。

P1/P2/P3 是规则型运营优先级，不是购买概率模型。互斥单位是用户与品类组合；同一用户可能在不同品类命中不同优先级，也可能已经在其他品类购买，不能将各层去重用户数相加。

## 四、品类机会识别

[品类机会分析](../sql/08_growth_opportunity_analysis.sql)覆盖两个周末有相关行为的 **9,077 个品类**。为控制小规模波动，先按两个周末较小的浏览用户数与意向用户数分别取正值分布 Q75：两个周末均至少 **271 名浏览用户、68 名意向用户**。规则先看规模，不依据转化下降幅度选阈值，得到 **1,551 个规模合格品类**；这仍不是显著性保证。

其中 **770 个机会品类**同时满足：浏览与意向用户均增长；购买用户增速低于浏览或意向增速；浏览→购买或意向→购买至少一项比例下降。

典型品类如下。增长率比较两个周末去重用户数；比例变化单位为百分点。

| category_id | 浏览用户增长 | 意向用户增长 | 购买用户增长 | 意向→购买比例变化 |
|---|---:|---:|---:|---:|
| 4756105 | 19.03% | 20.71% | 14.16% | -0.25 |
| 982926 | 18.40% | 24.51% | 7.04% | -0.84 |
| 2355072 | 10.51% | 11.98% | -5.29% | -0.58 |
| 4801426 | 22.17% | 26.55% | 8.02% | -0.91 |

**2355072** 的浏览与意向增长、购买用户下降，值得单独检查；**982926、4801426** 的意向增长明显快于购买增长，可作为承接检查与运营测试候选；**4756105** 的购买用户也在增长，但增速仍落后于流量与意向，说明机会识别不只关注购买规模下降。

品类层面的意向→购买是“同品类意向且购买 / 同品类全部意向用户”，不额外要求浏览，**与上一节平台嵌套漏斗的分母不同**。品类浏览→购买仍取浏览与购买交集，不把全部购买用户直接除以浏览用户；所有比例都不证明行为顺序。

category_id 是匿名编号，不能从这些差异推断商品属性、价格或未购买原因。候选品类按高意向未购买用户规模排名会偏向大品类，规模大不等于问题最严重。

将机会品类与用户优先级相交，得到：

| 候选层 | user-category pair 数 | 去重用户数 |
|---|---:|---:|
| P1 × 机会品类 | 658,968 | 349,857 |
| P2 × 机会品类 | 294,766 | 150,101 |
| P3 × 机会品类 | 1,629,056 | 621,772 |

整体共 **2,582,790 个组合、746,236 名去重用户**。这是一份候选池，不是实际可触达名单；若资源有限，优先从 P1 中选择适合验证的品类，并按用户去重、控制触达频率。

## 五、运营决策：将信号转为候选策略

- **P1：购物车召回、价格或权益提醒候选。**优先检查目标商品是否仍可购买、购物车状态是否有效；价格与权益提醒需要补充实时商品及权益数据。
- **P2：收藏提醒、内容强化候选。**围绕收藏兴趣测试商品内容与推荐，不假定与购物车人群使用相同策略。
- **P3：推荐优化、兴趣培育候选。**浏览门槛只是相对分位点，先采用低成本方式，不据此投入高成本激励。

以上均为**候选运营策略，实际效果需要线上实验验证**。当前分析不能证明提醒、优惠或推荐能够提升转化，也不能判断应补贴多少。

## 六、A/B Test 设计与现有模拟结果

[实验 SQL](../sql/07_ab_test_design.sql)和[统计评估 Notebook](../notebooks/07_ab_test_evaluation.ipynb)演示完整分析流程，历史数据没有真实 treatment。

实验前窗口为 **11/25–12/01**；资格为至少一次 cart、没有 buy，且最后活跃日期不早于 **11/30**。实验单位为 user_id，固定规则可复现地按约 50/50 分组。若真实上线，Treatment 假设收到购物车召回提醒，Control 维持原策略；**现有分组只是模拟标签，两组都使用原始历史行为**。

资格人群共 **211,091 人**：Treatment **105,898 人**，Control **105,193 人**。七项实验前特征的绝对 SMD 均小于 **0.005**，没有明显的已观测特征失衡，但这不证明所有特征完全一致。

结果窗口为 **12/02–12/03**。主指标 purchase_user_rate 定义为“结果窗口至少一次 buy 的用户 / 全部已分组用户”，不只统计后来仍活跃的人。

- Treatment 购买用户 **26,891 人**，购买用户率 **25.3933%**。
- Control 购买用户 **26,800 人**，购买用户率 **25.4770%**。
- 绝对 lift 为 **-0.0837 percentage point（百分点）**；它是两比例相减，不是相对百分比变化。
- 双侧两比例 z 检验 **p-value = 0.6589**，在 alpha = 0.05 下不拒绝两组比例相等的原假设；不表示已经证明两组完全相同。
- Treatment − Control 的 **95% CI 为 [-0.4552, 0.2879] percentage point**，包含 0，也容许该范围内的正负差异。
- 在双侧 alpha = 0.05、power = 0.80、1:1 分配及当前基准率下，当前样本量对应的正向 **MDE 约 0.5341 percentage point**。这是检测能力规划值，不是预期效果或必须达到的业务目标。

observed lift 接近 0，检验未提供明显组间差异的证据，与“没有真实 treatment”的设定相容。该模拟验证分析流程，不能证明购物车召回无效，也不能把 observed lift 解释为策略的因果效果。

## 七、真实线上实验如何落地

真实实验需补充 experiment_id、treatment_group、exposure_time、exposure_status、channel、message/coupon information，并关联 order_id、GMV / revenue 和 guardrail metrics。护栏可考虑退订或投诉、触达频次、退款、补贴与发送成本；当前数据无法评估这些指标。

实施流程为：

**目标人群圈选 → 随机分组 → treatment exposure → outcome observation → significance / CI / power → rollout decision**

上线前应冻结人群规则、指标与观察期限，按实际基准率、业务上有意义的最小提升和统计功效规划样本量，约定停止规则。记录真实送达与曝光，主分析保留全部随机分组用户，并避免同一用户因多个品类收到混杂策略。

扩量决策应结合置信区间、预先设定的业务收益要求与护栏，而不是只看 p-value，或要求观测 lift 超过 MDE。小规模实验样本不足时，结果不显著也可能只是检测能力有限；新机会池需要重新估算基准率和样本量，不能直接沿用模拟 MDE。

## 八、时间口径与数据泄漏

**SQL 07：**eligibility 与实验前特征只使用 **11/25–12/01**；outcome 只使用 **12/02–12/03**。两个窗口不交叉，资格与分组不依赖结果窗口，没有使用未来行为决定实验资格。

**SQL 08：**机会池使用 **12/02–12/03** 的近期行为，并利用完整九天判断目标品类是否已有 buy。因此它是 **12/03 结束后下一轮运营实验**的候选池，不能反过来用于 SQL 07 在 12/02 启动的历史模拟实验选人，否则会泄漏未来信息。

九天最终用户分层同样用于诊断与画像，不直接充当 SQL 07 的实验前资格。机会池的未来实验结果窗口应另行采集，当前数据无法提供。

## 九、项目限制

- 仅有九天，窗口之前与之后不可见；首次观测活跃不是注册日，前期无购买不等于历史从未购买。留存与购买行为存在左右截尾，不能推断长期复购或长期流失。
- category_id 匿名；无 price、promotion、coupon、channel、session_id、order_id，也无真实 treatment / exposure 日志。
- buy 是行为事件，不能计算真实订单转化率；没有收入与成本，不能计算 GMV / ROI。
- 无序集合漏斗不证明严格路径；品类差异、用户意向与购买沉寂都不能解释未购买原因，也不能证明召回策略有效。
- 两个等长周末仍可能受到未观测活动与用户构成影响。规模门槛降低小样本噪音，但不能消除波动或替代统计检验。
- 公开样本不代表平台全量；规则优先级不是预测模型，候选池规模不等于可触达人数或增量购买人数。

## 十、最终业务结论

1. **流量与购买人数都在增长，但购买承接相对落后。**日均浏览用户由 691,411 增至 937,907，浏览→购买比例均值却由 18.2785% 降至 17.1709%；经营判断应同时看规模与比例，优先检查意向到购买的承接。
2. **高活跃未购买人群有持续兴趣，适合作为验证对象。**105,478 人中 90.01% 有收藏或加购；先用近期品类信号缩小候选池，再验证触达增量，不将所有未购买用户同等处理。
3. **机会集中到用户与品类组合后，资源分配更具体。**770 个机会品类对应 P1 池 658,968 个组合、349,857 名用户；可以先挑选适合验证的品类做购物车召回实验，不能只按品类规模判断严重程度。
4. **购买沉寂不等于用户离开平台。**该群体 97.67% 在最后一天仍活跃；应考虑再购买场景，与平台不活跃人群采用不同运营假设。
5. **现有模拟不提供策略有效性的证据。**lift 为 -0.0837 个百分点且置信区间包含 0；下一步应采集真实触达与护栏数据，用随机实验决定是否扩量。

## 如果我是业务负责人，我会先做什么？

1. 从 **P1 × 机会品类**选择少量适合验证的品类，核对商品、可触达性与用户重复，启动真实购物车召回实验；这属于下一轮实验，不复用历史模拟的结果窗口。
2. 以 **purchase_user_rate** 为主指标，随机分组前固定资格、观察期与用户级触达规则。
3. 先依据业务最小提升确定 MDE 和所需样本量；观察期结束后结合 CI、增量收益与 guardrail 条件决定扩量，不将模拟 MDE 当成扩量门槛。
4. 为 **P2 和 P3 分别设计策略与实验**，区分收藏提醒、内容强化与推荐探索，避免混合触达后无法解释结果。
